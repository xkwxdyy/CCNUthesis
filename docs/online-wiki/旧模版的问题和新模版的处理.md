# 旧模版的问题和新模版的处理

---

本节主要讲一下邓国泰老师旧模版的使用有什么问题，以及在新模版中如何优化和完善的。

**注意**：首先我们要辩证看待这里所指的“问题”：
- 邓国泰老师在培训中所说的一些使用方式，是他在“ `CTeX` 套装，`pdflatex` 编译方式”下的使用方式，也许这个方式在 `ctex` 宏集还没有诞生之前是适用的，或者说可能只能那么用（注意 `ctex` 宏集和 `CTeX` 套装是两个完全不同的东西，具体可看慕子写的「 [我使用的 LaTeX 术语中文规约](https://zhuanlan.zhihu.com/p/45350320) 」）
- 但是随着 `TeXLive` 的开发和 `LaTeX` 的中文支持日渐完善，`CTeX` 套装早就不再推荐使用，而是使用 `TeXLive` 和 `ctex` 宏集在 `xelatex` 或 `lualatex` 编译方式下进行


关于旧模版的文件我有很多想说的，但是这里只挑一个 `simplify.def` 讨论一下：


## 关于旧模版的 `simplify.def` 文件

  这个容错，我不太赞成：
    - 在代码里，对的代码什么样就是什么样，所谓容错的代码只会减少代码的可读性
    - 看到 `\cdtos` 能想到这个是什么含义吗？`\cdots`意思清晰明了，`c` 表示 `center`，`dots` 表示点，加了 `s` 就说明是多个，稍微记一下就知道 `dots` 类的表示三个点，那么这个命令的效果就是垂直居中的三个点，不但看到这个命令马上知道含义，自己需要用的时候也能马上根据命令命名规范性马上想到，甚至是猜到对应的命令


个人秉持的观点

- 应当授人以渔，「[lshort-zh-cn](https://ctan.math.illinois.edu/info/lshort/chinese/lshort-zh-cn.pdf)」里有介绍如何自定义命令和环境，用户需要的话自己定义即可，如何命名完全取决于用户个人的喜好，用户用的也自然、舒服
- 对于绝大部分用户（特别是 `LaTeX` 初学者而言，使用的都会是 `VS code`, `TeXstudio` 等编辑器，这些编辑器是自带了自动补全功能（虽然如果从 LaTeX 的长期学习使用上看，能减少对自动补全的依赖是最好），极大减少了用户的使用负担。就拿 `VS code` 举例，即使是用户自定义的命令环境，在第一次手动输入后 `VS code` （或者说可能是安装的 `LaTeX-workshop` 的功能）就会记住，第二次输入前几个字母就会有弹窗提示选择自动补全，很方便。**完全没必要把名称简写，比如 theorem 写成 theo**

#### 关于选择题选项排版我想说的

其实在17届就已经有这个多个选项排版的需求了，但是旧模版并没有更新，而是等到下一届问到相同的问题才告诉你要怎么做。而且用户接口的杂乱增加了用户的使用负担和学习成本。

一个合格的模版需要不断根据用户需求和 `issues` 进行更新。需要从一些问题中找到共性来选择优化，比如在前几个版本中我并没有定义 `claim` （断言）环境，有用户和我反馈后，我应该做的，不是马上告诉他要怎么怎么定义，而是要从整个模版的使用上看，这个环境的定义是否具有普适性等等，答案是显然的，如果用户写数学相关的论文，有大概率会需要这个环境，于是我把这个环境的定义纳入了 `CCNUthesis` 处理的范畴而不是让用户自己定义就完事。减少用户的学习成本，让用户专心于内容本身，才是一个作为一个模版开发者应该做的。

### 关于 `\emph` 和 `\textbf`



- 旧模版的代码和处理
  ```latex
  动点$P$的点的轨迹叫做\textbf{圆锥曲线}.
  ```

- `CCNUthesis` 的代码和处理
  
  这是一个非常典型的内容和样式没分离的案例，非常推荐阅读一下 [liam](https://liam.page/)（`xprintlen`, `sduthesis` 和 `mcmthesis` 的开发者）写的「 [到底什么是「内容与样式分离」](https://liam.page/2019/03/18/separation-of-content-and-presentation/)」

  简单来说，
  - `\textbf`是格式命令，是开发者开发模版考虑的
  - `\emph`是语义命令，是用户应该使用的

  为什么要用 `\textbf{xxx}`，你可能会说，我想强调这个词，对了，“强调”这个语义才是你的本意，而 `\textbf` 是你“强调”的方式，应该使用 `\emph`。

  可能两者的效果差不多，甚至是一样的（这样看 `\emph`的定义），但是使用的思想是完全不一样的

### 关于 `~` 产生空格

- 旧模版的代码和处理
  
  在数学式和中文混排的时候，在数学式的左右需要加一个 `~` 才能得到空格，甚至需要极其麻烦的用查找替换（如果听了培训的同学就知道有多麻烦了）。

- `CCNUthesis` 的代码和处理
  
  邓老师称 `~` 是“可变的弹性距离”，这在 `CCNUthesis`中（更严格说是 `TeX Live` 中）是错误的！
  首先明确 LaTeX 中 `~` 的作用：
  「[lshort-zh-cn](https://ctan.math.illinois.edu/info/lshort/chinese/lshort-zh-cn.pdf)」的16页介绍了空格什么时候要用 `~`（**注意是西文的 `~`**）：
  ![](https://images.gitee.com/uploads/images/2022/0311/235920_4e8be6d7_7693572.png)
  也就是当你需要这个空格不会被断行的时候使用 `~` ，正文中很少使用，因为 `xelatex` 会正确处理好绝大部分的空格。在学位论文中会碰到的是
  ```latex
  图~\ref{xx} 说明了
  表~\ref{xx} 也说明了
  定理~\ref{xxx} 向我们阐述了
  Donald~E. Knuth 是一位...
  ```
  效果是
  ```latex
  图 xx 说明了
  表 xx 也说明了
  定理 xx 向我们阐述了
  Donald E. Knuth 是一位...
  ```

  在 `CCNUthesis` 中数学式和中文混排，即使没有`~` 也能得到正确的空格
  ```latex
  中文$x^2$中文

  中文 $x^2$ 中文
  ```
  两种方式都能得到正确的空格
  ![](https://images.gitee.com/uploads/images/2022/0312/000957_2d974164_7693572.png)
  但是推荐后者，让内容更清晰。（更多的代码规范指南欢迎阅读 [zepinglee](https://github.com/zepinglee)（`thuthesis(清华大学学位论文模版)` 维护者，`ustcthesis(中科大学位论文模版)` 开发者和维护者）写的 「 [LaTeX2e代码规范](https://gitee.com/zepinglee/latex2e-style-guide) 」）

### `\caption` 和 `\label`

- 旧模版的代码和处理
  ```latex
  \begin{figure}
    ...
    \caption{\label{fig1} 曲线说明}
  \end{figure}
  ```

- `CCNUthesis` 的代码和处理
  
  旧模版的这个用法是不推荐的（没说是错的，效果是没问题的），一般只有 `\footnote` 的标签才会在参数里面（要注意本科生院的《 关于毕业论文注释与参考文献著录格式修订的通知》规定了“理工科的论文注释不使用脚注” 也就是不能使用 `\footnote` 命令）
  `\caption` 是 `\caption`，`\label` 是 `\label`。一个命令有一个语义，一般不嵌套，`\caption` 标题， `\label` 打标签，分工明确
  ```latex
  \begin{figure}
    ...
    \caption{曲线说明}
    \label{fig:曲线说明}
  \end{figure}
  ```
  另外，`\label` 的参数不建议是 `fig1` 这样没有具体含义的，建议是 `<type>:<description>`，`<type>` 可以是简写或全称，看个人喜好；在 `CCNUthesis` 中 `<description>` 可以是中文，比如 `\label{theorem:数列极限的柯西收敛准则}`，`\label{fig:连续函数空间无穷范数收敛的几何解释}`。

  这样的优点：
  - 一眼就知道 `label` 的内容是什么，在 `ref` 的时候更容易明确内容（VScode 正确配置后使用 `\ref` 时也会有自动补全提示可供选择）
  - 这样的话，即使调整了图片的顺序也依旧结构清晰，而不用手动去重新写 `fig1`，`fig2`


### 关于定理内容的「括号倾斜问题」

- 旧模版的代码和处理
  ```latex
  \begin{defi}[...]\label{...}
    \textup{坐标轴上一个动点$P$到定点~(焦点$F$)~的距离与到定直线...}
  \end{defi}
  ```

- `CCNUthesis` 的代码和处理
  
  我说几点：
    - 这个应该属于定理内的格式处理，应该在定义定理的时候就要进行处理，而且这是开发者的工作，而不是用户
    - 一般的用户使用的还是中文（如果有英文的需求可能还得单独处理，比如 `thuthesis` （清华大学学位论文模版）有中英文的版本，以后有需求的话再慢慢开发），所以个人认为这个括号理当使用中文括号
    - `CCNUthesis` 的定理正文的格式设置过，西文括号是不会倾斜的
    - `~`在上面讨论过，这里不需要，甚至应该不加空格，即使括号两端有括号也会被 `ctex` 宏集+ `xelatex` 编译方式自动处理（这才是现代 LaTeX 使用中文的正确方式，而不是 `CTeX` 套装），减少用户使用成本（即还要担心这个括号周围要不要加括号）
  ```latex
  \begin{theorem}
    测试
    \begin{itemize}
      \item 中文（括号）没输入空格的效果
      \item 中文 （括号） 输入空格的效果
      \item 西文(括号)没输入空格的效果
      \item 西文 (括号) 输入空格的效果
    \end{itemize}
  \end{theorem} 
  ````

### 定理和证明环境之间可能会出现额外的间距

- 旧模版的代码和处理

  因为间距的处理导致定理和证明环境之间有一段多的间距时，旧模版是在定理前面的内容加了一个
  ```latex
  \bigskip
  ```
  命令，产生一个额外的间距

- `CCNUthesis`

  非常不建议用户自己使用 `\bigskip`, `\vspace{}` 等命令在学位论文的撰写中自己添加额外的垂直间距：
    - 如果不是章节末尾的话会看起来很奇怪
    - 这个东西本身就属于格式的范畴，用户不应该进行干涉和考虑
    - 绝大部分的时候，在没定稿之前，你不知道前面的内容是否会增添删改，一改动的话，那个间距可能就没了，反而你加的 `\bigskip` 却还是生效的


### 证毕符号在额外的一行

- 旧模版的代码和处理

  旧模版把 `proof` 环境去掉了，然后自己手动加了“解”和证毕符号，甚至还想用 `\vspace{}` 让证毕符号上去
  ```latex
  \eqno{\Box}
  ```

- `CCNUthesis` 的代码和处理
  
  完全没必要手动输入，还是那句话，格式的东西不应该交给用户。正确的方式是使用 `\qedhere`:
    - `qed` 可能有不少用户见过：
      >“QED=quod erat demonstrandum (拉丁文)，出现在数学证明末尾，代表证明的结束符□，意思是证明完毕（证毕），也有Q.E.D.等相似写法。”（摘自百度百科）
    - `here` 表示这里
    - 合在一起就是：把证毕的符号放在这里，是一个用户层的语义命令。让我们看看如何使用
  ```latex
  \begin{proof}
    test
    \[
      \int_{0}^{1} x^2 \dd{x}
    \]
  \end{proof}

  \begin{proof}
    test
    \[
      \int_{0}^{1} x^2 \dd{x}  \qedhere
    \]
  \end{proof}
  ```
